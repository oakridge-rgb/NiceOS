# NiceOS

A **purple/blue reskin of Debian 13 (trixie) + XFCE** — a real, bootable Linux
distribution where every visible layer is rebranded, while the package base
(kernel, drivers, updates) stays stock Debian. Think Zorin OS or Linux Mint:
a remix, not a fork.

**Target: VMs (QEMU/VirtualBox).** Nothing here modifies the Debian core.

| Layer | What you see | How it is done |
| --- | --- | --- |
| Boot menu (installed system) | Dark indigo background, NiceOS menu | `usr/share/grub/themes/niceos/theme.txt` + `GRUB_THEME` in `/etc/default/grub` |
| Boot splash | NiceOS orb on an indigo→blue gradient | Plymouth two-step theme + `update-alternatives` hook |
| Login screen | Wallpaper background, Niceos theme, clock | LightDM GTK greeter config |
| Desktop | Mac-like top panel + bottom auto-hide dock | XFCE panel defaults via `/etc/skel` xfconf XML |
| GTK theme | Arc-Dark base, purple `#7C4DFF` → blue `#2979FF` accents | `Niceos` theme in `usr/share/themes/` |
| Icons | Papirus-Dark | stock Debian package |
| Wallpaper | Custom purple/blue gradient art | generated by `assets-src/generate_assets.py` |
| App menu | NiceOS orb button, curated favourites | Whisker menu panel defaults |
| Identity | `os-release` says `NiceOS 1.0`, MOTD, issue, hostname | chroot hook `0100-niceos-branding` |
| Installer | "Install NiceOS" (Calamares with NiceOS branding + slideshow) | `usr/share/calamares/branding/niceos/` + polkit rule |
| Welcome app | First-login dialog with installer shortcut | `usr/bin/niceos-welcome` (zenity) |

## Build

### With Docker (any Linux host)

```sh
docker build -t niceos-builder .
docker run --rm --privileged -v "$PWD":/niceos niceos-builder
```

### Native (Debian 13 host)

```sh
sudo apt install live-build xorriso squashfs-tools grub-pc-bin \
     grub-efi-amd64-bin mtools fakeroot
sudo ./build.sh
```

### With GitHub Actions

The workflow ships at **`ci/build.yml`** — GitHub rejects pushes that add
`.github/workflows/*` using a personal access token without the `workflow`
scope, so the file is versioned one directory up. Enable CI with:

```sh
git mv ci/build.yml .github/workflows/build.yml
git commit -m "Enable CI" && git push
```

(or add it through the GitHub web UI). From then on, every push to `main`
builds `NiceOS-1.0-amd64.iso` and uploads it as an artifact; pushing a tag
`v*` also publishes it as a Release.

Output: `binary.iso` — an ISO-hybrid image (BIOS + UEFI bootable).

## Try it (VM)

```sh
qemu-system-x86_64 -enable-kvm -m 4G -smp 4 -nic user,model=virtio-net-pci \
    -boot d -cdrom NiceOS-1.0-amd64.iso
```

Live session: user `user`, password `live`. The welcome dialog offers
**Install NiceOS** (Calamares); the same entry is in the app menu.

## Customize

- **Colors** — edit the palette in `assets-src/generate_assets.py`
  (`PURPLE` / `MID` / `BLUE` / `DARK_A` / `DARK_B`) and the defines at the top
  of `config/includes.chroot/usr/share/themes/Niceos/gtk-3.0/gtk.css`, then
  run `python3 assets-src/generate_assets.py` (needs Pillow) and commit.
- **Panels/dock** — edit
  `config/includes.chroot/etc/skel/.config/xfce4/xfconf/xfce-perchannel-xml/xfce4-panel.xml`.
- **Packages** — `config/package-lists/niceos.list.chroot`.
- **System branding** — `config/hooks/live/0100-niceos-branding.hook.chroot`.

## Notes and limitations

- The **live ISO's own GRUB menu** is generated by live-build and stays stock;
  the themed GRUB applies to the **installed** system (Calamares carries
  `/etc/default/grub` over). The Plymouth splash covers the live boot anyway.
- The Plymouth splash is a static logo on a gradient (no spinner frames) —
  minimal, safe, and fast to build.
- Only `amd64` is configured. Hardware outside VMs is untested by design
  (virtio drivers cover QEMU; VirtualBox needs no extras).
- IDENTITY: `os-release` sets `ID=niceos` / `ID_LIKE=debian`. Software
  beyond Debian's repos that hard-checks `ID=debian` may not recognize it.
- Built with Debian's official `live-build`; the CI pins trixie's version so
  the runner distro doesn't matter.
